# 快速开始

这是一套可按需取用的方法，不要求先通读全部文件，也不要求每个项目创建全部模板。先花几分钟判断研究类型、当前阶段、截止日期和每周可投入时间，再只读当前任务需要的细则。

## 先判断论文类型

| 研究设计 | 用法 |
|---|---|
| 单企业诊断与改进：解释现状、问题和原因，并提出方案 | 可使用六阶段主流程及主题关系表 |
| 企业战略规划、商业模式/创业案例、经验总结或实施评价 | 不默认套用“问题—原因—方案”链。先按开题确定研究问题、分析单位和论证结构，再选用证据追溯、文献核对、写作和排版细则；主题关系表按目标、备选、评价维度、证据和结论改写 |
| 定量实证、多案例比较、本科论文或期刊论文 | 本 Skill 的章节结构和阶段标准不直接适用；证据追溯、参考文献核对和格式脚本等通用部分可单独借用 |

论文类型或开题方法不明确时，先让作者提供开题中“研究问题、研究方法、研究范围”三项，不要根据题目猜研究设计。

## 先判断用户是不是作者

用户替别人审稿（同学互审、导师或学长看快定稿）时，走**第三方审阅**：直接按 `references/整体审查清单.md` 的“第三方审阅”做，只读不改，不建决定日志等过程文件，产出一份带总体结论和严重度的《审查报告》，修改与否交作者决定。下面的工作路径只适用于用户是作者本人的情况。

## 选择工作路径

**标准路径**适合从开题开始、研究环节多或需要完整过程记录的项目：阶段 1 对标 → 阶段 2 搭框架 → 阶段 3 取证 → 阶段 4 成文 → 阶段 5 合稿 → 阶段 6 迭代审查。

**轻量路径**适合已有开题、时间紧或只做局部工作的项目：

1. 确认研究问题、截止日期、学校 AI 规定和当前导师意见。
2. 做一张“核心主张—证据—正文位置”清单；只在存在多条相互关系时再展开主题关系表。
3. 先写一节最关键的分析，逐项标出事实来源、反例/不确定性和待作者判断处。
4. 证据缺失时先决定替代、缩小范围、降低结论强度或回到研究设计；不能把核心缺口留给送审。
5. 只对本轮改动影响的章节做联动检查；送审前再做一次完整的内容、字数、格式和目录检查。

轻量路径不降低证据标准，只合并过程记录。一个表可以同时承担证据台账和主题关系记录；不必为了使用 Skill 而把同一信息抄进多个文件。

## 模板是菜单，不是入场清单

- 所有项目都需要能追溯核心主张的依据；可用一张简表，不一定要独立建立完整台账。
- 只有证据确实缺失时才启用证据缺口决策表；只有理论工具进入分析时才启用理论映射表。
- 范文少、论文类型不适配或局部任务不需要时，可跳过范文统计或整套阶段流程，并记录理由。
- 决定日志、快照和完整模板用于复杂或多轮协作；一次性改写、格式修正等局部任务不必建全套目录。

## 按阶段找细则

| 现在要做什么 | 先读 |
|---|---|
| 对标、研究问题或结构 | `references/对标与搭框架.md` |
| 访谈、问卷或数据缺失 | `references/取证.md`；涉及访谈/问卷再读 `references/访谈与问卷.md` |
| 写章节、看负例或整理理论 | `references/成文.md`、`references/负例与改写示例.md`；按需用 `templates/理论映射表.md` |
| 生成 Word / 检查目录 | `references/合稿与检查.md`、`scripts/README.md` |
| 吸收导师意见、提交前检查或披露 AI 使用 | `references/整体审查清单.md`；按学校规定用 `templates/AI使用说明模板.md` |
| 替别人审稿 | `references/整体审查清单.md` 的“第三方审阅” |
| 核对角标与英文文献 | `scripts/check/ref_check.py`、`scripts/check/crossref_check.py`（见 `scripts/README.md`） |

计划时间时，作者先填写每周可投入时数、截止日、导师反馈周期和必须完成的学校流程；本 Skill 不假设所有学生有相同的工时或导师响应速度。进度模板见 `templates/导师审阅与进度.md`。
