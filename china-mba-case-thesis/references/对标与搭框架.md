# 阶段 1 对标、阶段 2 搭框架：细则

## 阶段 1：对标

### 收集范文

- **优先级**：导师推荐 → 本院同类（近几年、同一专业学位、同为单企业案例型）→ 本校其他学院 → 外校 → 期刊论文。期刊论文只用来看理论和文献，不参照它的结构。
- **数量与代表性**：本院同类尽量找齐，外校只作补充。没有通用的最低篇数门槛；记录每组来源、年份、学位类型、案例类型、可提取文本比例及缺失情况。样本少或选择偏差明显时，只报告观察到的个案，不把中位数或关键词频次当成规范，也不据此决定章节结构、字数比例或图表目标。
- **存放**：作者从学校数据库下载原文，放在 `参考论文/` 下，按来源分子目录（子目录名就是统计表里的“分组”）。

### 统计

```
python scripts/survey/survey_samples.py 参考论文 -o tmp/范文统计.md --keywords 关键词1,关键词2
```

脚本统计每篇的页数、汉字数、章节骨架、图表数、文献数、有无附录和关键词频次，并给出描述性统计。只有来源和类型大体可比、样本覆盖足以支撑比较时，才把汇总值用于建议；否则逐篇描述并标注局限，不以小样本中位数作目标。关键词按要判断的边界来选。扫描版 PDF 提取不到文字时，手工翻目录并把该篇标作“文本统计缺失”，不要把缺失误当成关键词零次。

脚本只给数字。下面这些要助手读几篇有代表性的范文才能回答：

- 各章篇幅比例，核心章大约占多少；
- 现状与问题、原因是合成一章还是分开写，保障措施是否单独成章；
- 常用哪些研究方法和理论工具，问卷和访谈的材料放在正文还是附录；
- 图的类型，表格放什么内容；
- 致谢、附录的位置和内容；
- 参考文献的构成：期刊、学位论文、英文文献、近五年文献各占多少。

### 写《范文横向分析》

按模板 `templates/范文横向分析.md` 写，结论落到三点：结构要不要动；内容边界（哪些能写、哪些不写）；篇幅、图表和文献大致各要多少。每条结论都写明依据，即哪几篇范文、哪个统计值。和开题报告或作者原先的设想不一致的地方单独列出，交作者决定。

这是一次性文件：结论合并进决定日志和写作大纲后，原件移入 `归档/一次性/`。

## 阶段 2：搭框架

### 以开题为准

题目、研究问题、研究方法、研究范围都以获批的开题报告为准。对标中发现结构需要调整的（如两章合并），先给备选方案和依据，由作者决定；涉及题目、研究方法的改动，要作者和导师确认，并记入决定日志。

### 先画主题关系表

主题关系表是原则 3（论证关系贯穿全文）的落地形式，后面的目录、取证、成文、审查都以它为准。模板见 `templates/主题关系表.md`。

- **稳定标识，不强求配对**：为问题、原因、方案、效果分别编号并使用统一短名；按实际论证关系记录一对一、一对多或多对多。问题和原因可以合并或拆分，方案可共同解决多个问题；不能为凑齐行列而拆出没有独立证据的子问题。
- **记录关系及出处**：每条“原因导致问题”“方案回应原因/问题”“指标衡量预期变化”关系都注明依据或作者待确认状态。章节位置是导航，不要求各类条目数量一致；未覆盖的问题、原因或指标需说明取舍理由。
- **证据列**写清每行靠什么支撑（哪份数据、哪组访谈、哪篇文献），取证阶段据此倒推数据需求。
- **多对多**：一个原因可能解释多个问题，一个方案也可能回应多个原因/问题；分别记录关系和依据，不把整个问题集合压成一条看似整齐的链。
- **查漏**：每条方案至少回应一个有依据的问题或原因；未处理的原因注明范围、证据或可行性限制；对应不到研究问题或证据的方案删掉，或回到阶段 2 说明研究设计如何支持它。

逐条检查关系是否说得通：什么证据支持问题判断，哪些原因解释它，方案回应哪一项问题/原因，效果指标如何衡量预期变化。关系可以跨行或多对多；无法说明的连接是论证断点，不用强行补成对称行。

主题关系表是活文件。标题、问题名称或口径改了，先改这张表，再联动各章、摘要、结论和图。

**旧模板迁移：** 如果已有项目使用 `主题线对应表.md`，将定位红线转入本表；把旧表中的问题、原因、方案、效果分别整理为条目，并把它们之间有依据的联系记录到“关系”表。原证据只复制到它实际支持的条目或关系上；不要沿用旧表按一行一个问题、各类数量相等的排法。

### 定位红线

写在大纲开头，用一两句话说清本文写什么、不写什么，例如：

- “只写为什么做、值不值得、能不能做成，不写怎么实现”；
- “写管理流程，不写设备参数和技术实现”；
- “研究范围限于生产环节，不含采购和售后”。

红线来自开题报告界定的范围和范文实测的内容边界。成文时和整体审查时都按它判断是否越界。红线定了就记入决定日志。

### 写作大纲与论文目录

- **论文目录**写到三级标题，标题须准确表达该节内容。目录中问题、原因、方案的数量可以不同；核对每个标题是否有研究问题、证据和范围依据，不以数量相等作为完成标准。
- **写作大纲**在目录的基础上，为每一节写明：要回答什么、主要论据和数据来源、配哪些图表、计划字数。
- **字数**：总字数按学校要求，各章比例参考可比范文的观察结果和本研究内容需要，核心章通常占得较多。样本不具代表性时不套用比例。Word 生成脚本每次打印各章汉字数，合稿时对照大纲检查。
- **图表**：逐张说明用途、位置和数据来源。范文数量只作为可比样本的描述参考；样本有限时不把中位数转成目标数，不为凑数加图表。

### 方法说明

为每个理论工具单独写一段说明，内容包括：

- 原理是什么（引文献）；
- 在本文的哪一步用；
- 输入是什么（哪些数据或材料）；
- 输出什么结论。

另填《理论映射表》（模板 `templates/理论映射表.md`），把理论构念/要素映射到本文分析维度、具体证据、发现和方案。若某个理论要素没有可用证据，标出缺口并按阶段 3 处理；不要仅因理论列出了该要素，就断言案例企业存在相应问题。一个证据可支持多个维度，一个维度也可由多种证据共同支撑，逐项说明即可。

**避免循环论证。** 选用某个工具，理由应来自问题本身的特征，而不能来自用这个工具得出的结论。例如，用某个理论的要素清单去对照企业，得出“企业缺少这些要素”，再用同一个理论来改进，这就是循环论证。分析问题要靠独立的证据（数据、访谈、记录），理论用来组织分析和设计方案，不能直接用来证明问题存在。

理论基础章只写方法说明里用得到的理论。

### 完成标准

任何一节都能在主题关系表、理论映射表或大纲中找到依据与用途；样本局限、范围红线、里程碑和各章字数已经作者确认并记入决定日志。
