# 阶段 1 对标、阶段 2 搭框架：细则

## 阶段 1：对标

### 收集范文

- **优先级**：导师推荐 → 本院同类（近几年、同一专业学位、同为单企业案例型）→ 本校其他学院 → 外校 → 期刊论文。期刊论文只用来看理论和文献，不参照它的结构。
- **数量**：本院同类尽量找齐，外校只作补充。某一组样本很少时，结论里写明“样本少”，不据此下定论。
- **存放**：作者从学校数据库下载原文，放在 `参考论文/` 下，按来源分子目录（子目录名就是统计表里的“分组”）。

### 统计

```
python scripts/survey/survey_samples.py 参考论文 -o tmp/范文统计.md --keywords 关键词1,关键词2
```

脚本统计每篇的页数、汉字数、章节骨架、图表数、文献数、有无附录和关键词频次，并给出中位数。关键词按要判断的边界来选，例如想知道技术细节写到什么程度，就选“数据库”“算法”“系统架构”这类词。扫描版 PDF 提取不到文字，脚本会给出警告，这几篇手工翻目录。

脚本只给数字。下面这些要助手读几篇有代表性的范文才能回答：

- 各章篇幅比例，核心章大约占多少；
- 现状与问题、原因是合成一章还是分开写，保障措施是否单独成章；
- 常用哪些研究方法和理论工具，问卷和访谈的材料放在正文还是附录；
- 图的类型，表格放什么内容；
- 致谢、附录的位置和内容；
- 参考文献的构成：期刊、学位论文、英文文献、近五年文献各占多少。

### 写《范文横向分析》

按模板 `templates/范文横向分析.md` 写，结论落到三点：结构要不要动；内容边界（哪些能写、哪些不写）；篇幅、图表和文献大致各要多少。每条结论都写明依据，即哪几篇范文、哪个统计值。和开题报告或作者原先的设想不一致的地方单独列出，交作者决定。

这是一次性文件：结论合并进决定日志和写作大纲后，原件移入 `归档/一次性/`。

## 阶段 2：搭框架

### 以开题为准

题目、研究问题、研究方法、研究范围都以获批的开题报告为准。对标中发现结构需要调整的（如两章合并），先给备选方案和依据，由作者决定；涉及题目、研究方法的改动，要作者和导师确认，并记入决定日志。

### 先画主题线对应表

主题线对应表是原则 3（一条逻辑链贯穿全文）的落地形式，后面的目录、取证、成文、审查都以它为准。模板见 `templates/主题线对应表.md`。

- **每行一个问题**，起一个统一的短名，全文都用这个名称。问题从开题报告的研究问题和企业现状出发，不凭空添加。
- **各列是这个问题在各章的位置**：问题小节、原因小节、方案小节、效果指标。七章结构（原因或保障单独成章）加列，两段式结构（问题与原因合一）并列，按实际章节调整。
- **证据列**写清每行靠什么支撑（哪份数据、哪组访谈、哪篇文献），取证阶段据此倒推数据需求。
- **多对多**：一个原因可能同时导致几个问题，此时方案对应原因，而不是对应问题，并在表下写明关系。
- **查漏**：每条方案至少对应一个原因；有原因而没有方案的，写明为什么不在本文解决（如超出研究范围）；对应不到原因的方案删掉，或者回头补上原因分析。

画完横着读每一行，要能说成一句话：因为某个原因，出现了某个问题，所以采取某项方案，预期某个指标得到改善。说不通的行，就是论证链上的断点。

对应表是活文件。标题、问题名称或口径改了，先改这张表，再联动各章、摘要、结论和图。

### 定位红线

写在大纲开头，用一两句话说清本文写什么、不写什么，例如：

- “只写为什么做、值不值得、能不能做成，不写怎么实现”；
- “写管理流程，不写设备参数和技术实现”；
- “研究范围限于生产环节，不含采购和售后”。

红线来自开题报告界定的范围和范文实测的内容边界。成文时和整体审查时都按它判断是否越界。红线定了就记入决定日志。

### 写作大纲与论文目录

- **论文目录**写到三级标题，问题小节的标题直接写出问题（见 `references/成文.md`）。目录里问题、原因、方案小节的数量要和对应表一致。
- **写作大纲**在目录的基础上，为每一节写明：要回答什么、主要论据和数据来源、配哪些图表、计划字数。
- **字数**：总字数按学校要求，各章比例参照范文实测，核心章（现状与问题、方案）占得最多。Word 生成脚本每次都会打印各章汉字数，合稿时对照大纲检查。
- **图表**：总量参照范文的中位数，每张图表注明放在哪一节、数据从哪里来。

### 方法说明

为每个理论工具单独写一段说明，内容包括：

- 原理是什么（引文献）；
- 在本文的哪一步用；
- 输入是什么（哪些数据或材料）；
- 输出什么结论。

**避免循环论证。** 选用某个工具，理由应来自问题本身的特征，而不能来自用这个工具得出的结论。例如，用某个理论的要素清单去对照企业，得出“企业缺少这些要素”，再用同一个理论来改进，这就是循环论证。分析问题要靠独立的证据（数据、访谈、记录），理论用来组织分析和设计方案，不能直接用来证明问题存在。

理论基础章只写方法说明里用得到的理论。

### 完成标准

任何一节都能在对应表或方法说明里找到它在逻辑链上的位置；定位红线和各章字数已经作者确认，并记入决定日志。
