# 阶段 4 成文：细则

## 正文

- **顺序**从核心章节往外扩：现状与问题 → 方案 → 效果与保障 → 理论综述 → 绪论 → 结论 → 摘要。先写现状与问题是因为它决定了全文的问题和口径，理论综述和绪论要为它服务，写在后面才知道该铺垫什么。
- **每章一个源稿**。章首用备注行写版本、日期、依据和脱敏口径；章末列“待补数据与待确认事项”，所有占位都登记在这里，合稿前清零。
- **原因小节第一句就给结论**。标题对齐之后（“××问题的原因分析”），标题本身不再带信息量，靠首句补回来。
- **问题小节的标题直接写出问题**（“过程检验流于形式，质量依赖末端把关”），不写“过程检验现状”这种看不出问题的标题。评审看目录就要能看出论文在说什么。
- **MBA 论文谈管理，少谈技术**。技术素材（架构、设备、算法）可以留，但压缩篇幅，并且每段技术判断都要落到管理结论上（可行性、成本、风险、验收标准）。数据库设计、E-R 图、UML、开发环境、算法伪代码一般不写，具体以本院范文实测为准。
- **方案不要和现状分析打架**：现状里说“不能做”的事，方案里不能靠它实现；现状里说“已经在做”的，方案里不能当作新举措。
- **预期效果写成目标**（“按测算报废率可降低约 N 个百分点”），不写成已经发生的结果。
- **摘要最后写**，主旨与原因分析、结论三处一致。字数按学校规范（硕士常见 1000 字左右）。

## 各章写法

章名以开题报告为准，下面按章的作用来称呼。每种章写明要回答什么、常见结构和评审常挑的毛病；结构以本院范文实测为准。

### 绪论

- **要回答**：为什么研究这家企业的这个问题，研究什么，怎么研究。
- **常见结构**：研究背景 → 研究目的与意义 → 国内外研究现状（有的学校放在理论章）→ 研究内容与方法 → 技术路线 → 论文结构或创新点（看本院惯例）。
- **常见扣分点**：
  - 背景从宏观政策讲起，好几页才落到企业。应当在一两段之内从行业落到企业的具体问题。
  - 研究意义写成套话（“丰富了相关理论”“具有重要的现实意义”）。要写具体：对谁有用，解决什么问题。理论意义写不出来的，按本院惯例少写或不写。
  - 研究现状只罗列“某某（年份）认为……”。应按主题归类，每类末尾一句述评，最后点出已有研究的不足和本文的切入点。
  - 列出的研究方法正文里没用上，或者正文用了这里却没写。以开题报告为准，前后对照。
  - 技术路线图和实际章节对不上。

### 理论基础与文献综述

- **要回答**：本文用到哪些理论和工具，各用在哪一步。
- **常见结构**：概念界定 → 相关理论（每个理论写内涵、要点、在本文的适用性）→ 分析工具 → 本章小结（这些理论如何组成本文的分析框架）。
- **常见扣分点**：
  - 写成教科书，堆了正文从未用到的理论。只写方法说明里用得到的（见 `references/对标与搭框架.md`）。
  - 理论和后文脱节，后面各章没有回扣理论的要点。
  - 概念界定照抄百科。引用有出处的定义，说明本文采用哪一种。

### 现状与问题

- **要回答**：企业现在是什么样，问题是什么，有多严重。
- **常见结构**：企业概况（只写和主题相关的）→ 现状描述（按流程或按要素）→ 问题归纳（每个问题一小节）。写法见上面“正文”各条和 `example/src/第3章-现状与问题分析.md`。
- **常见扣分点**：
  - 概况写成企业宣传材料。
  - 现状只描述，不评价。
  - 问题缺少数据支撑。
  - 问题之间互相重叠，一个其实是另一个的表现。

### 原因分析

- **要回答**：每个问题为什么会出现。
- **常见结构**：按问题逐一分析；或者先用鱼骨图之类的工具按维度归类，再对应回问题。每个原因小节第一句就给结论。
- **常见扣分点**：
  - 原因只是把问题换个说法（“质量差是因为质量管理不到位”）。
  - 原因停在表层（“员工意识不强”），没有追到制度、流程、资源上。
  - 原因全是外部的，企业无能为力。
  - 原因和问题对不上。对照主题线对应表检查。

### 方案

- **要回答**：针对每个原因做什么，怎样落地。
- **常见结构**：方案目标与原则 → 总体思路（常配一张框架图）→ 分项方案（每项对应主题线对应表里的原因）→ 实施计划（步骤、责任部门、时间安排）。
- **常见扣分点**：
  - 方案和原因不对应：有原因没方案，或者方案对应不到任何原因。
  - 方案空泛（“加强培训”“提高认识”），说不清谁来做、做什么、怎么检查。每项方案至少写清责任主体、具体做法和衡量标准。
  - 方案超出企业的能力或研究范围（小企业上大系统；开题报告没有涉及的环节）。
  - 方案和现状矛盾（见上面“正文”）。

### 效果与保障

- **要回答**：方案实施后能带来什么，靠什么保证落地。
- **常见结构**：预期效果（指标、现状值、目标值、测算依据）→ 保障措施（组织、制度、人员、资源等，按本院惯例）→ 风险与应对（有的学校要求写）。
- **常见扣分点**：
  - 预期效果没有测算依据，或者把目标写成了已经实现的结果。目标值要写清来源：企业自定的目标、行业或标杆参照、按方案内容推算。推算的，列出推算过程。
  - 效果指标和现状章的指标对不上（名称或口径不一致）。
  - 保障措施空泛，放进哪篇论文都能用。每条保障措施都要对应某项方案落地时的具体障碍。

### 结论

- **要回答**：本文得出了什么结论，有什么局限。
- **常见结构**：研究结论（沿着问题、原因、方案的主线概括，每条一段）→ 不足与展望。
- **常见扣分点**：
  - 重复摘要，或者逐章复述目录。
  - 出现正文没有的新观点或新数据。
  - 和摘要、原因分析的主旨不一致。
  - 展望写成套话。不足要写具体，例如数据期间短、样本少、方案尚未经过实施检验。

### 摘要

- **要回答**：用一页让评审知道研究了什么问题、用了什么方法、得出了什么结论。
- **常见结构**：背景与问题（一两句）→ 研究方法 → 主要发现（问题与原因）→ 方案要点 → 预期效果或意义。
- **常见扣分点**：
  - 背景写得太多。
  - 只说“提出了改进方案”，不说方案是什么。
  - 和正文的结论不一致。
  - 英文摘要和中文摘要内容对不上。

## 文风底线

具体规则以决定日志为准，下面是中文管理类学位论文的通行底线：

- 书面、客观。不用口号式概括（“检验很到位，预防却缺位”），不用口语（“机子”“弄清楚”）。
- 避免机械列举：“首先 / 其次 / 最后”“其一 / 其二”“一是 / 二是”少用，靠句子内部的因果、递进衔接。
- 方案表述肯定，不写“本文建议”“近期 / 远期”这种留余地的说法。
- 正文不写章节交叉引用（“见第 3 章”“如 3.2.2 节所述”）。
- 同一概念全文只用一个词（“不良品”和“次品”、“返工”和“返修”不混用）。
- 脱敏：企业用代称（“YT 公司”），不写企业全称、客户名、供应商名、设备型号；不写作者与企业的个人关系；不写实地调研的具体起止时间（外审会追问）。
- 中英文和数字之间加空格，全角中文标点。

## 润色顺序

先做句式层面的改写（减少模板化套话、使句式多变），再做书面化和去口语化，最后查错。原因是任何追求句式多变的改写都容易带进口语和口号式表达，它之后必须再有一轮书面化检查；反过来排就会把刚清理干净的口语又带回来。每轮润色前先快照。

润色的目的是表达清楚、合乎学术规范，不是降低 AIGC 检测率。助手不做以规避检测为目的的改写；助手起草或改写过的段落，由作者逐段审读并改成自己的表述（见 SKILL.md 第一节）。

## 参考文献

- **分工**：助手定检索方向、写检索式（数据库、主题词、来源类别、年份），记入《参考文献待办》；需要登录的数据库（知网等）由作者检索并下载原文；开放可查的文献由助手上网检索，对照出版方页面或 Crossref 核对；也从范文的参考文献表里筛选候选。
- **选文规则**由作者定，常见的有：期刊论文为主、少引硕士学位论文、近五年优先、中文优先核心期刊、标准和政策文件可引作背景依据。总条数和构成（期刊 / 专著 / 学位论文 / 英文 / 近五年占比）对照本院范文的中位数。
- **逐条核对**题名、作者、刊名、年、卷期、页码，和原文 PDF 刊头、数据库页面或 Crossref 对上，结果记入《参考文献核对清单》，每条写明依据。核不到的项目留空，不编。
- **核对渠道**：
  - 有 DOI 的：打开 `https://doi.org/<DOI>` 跳转到出版方页面；或者查 Crossref，`https://api.crossref.org/works/<DOI>` 返回题名、作者、刊名、年、卷、期、页码。
  - 没有 DOI 的英文文献：查 `https://api.crossref.org/works?query.bibliographic=<题名和第一作者>&rows=5`，返回结果里有完全吻合的条目才算核对通过，只有相近的不算。
  - 中文期刊：多数没有 DOI 或 Crossref 记录。公开可查的渠道有国家哲学社会科学文献中心（ncpssd.cn）、期刊官网的过刊目录、知网和万方的检索结果页（题录可见，全文要登录）。助手查不到的，列给作者到学校数据库核对。
  - 国家标准：国家标准全文公开系统（openstd.samr.gov.cn）；政策文件：发文机关官网。
  - 图书：出版社官网或国家图书馆联机目录。
- **著录格式** GB/T 7714—2015，正文顺序编码制、方括号上标。引文标注不放在标题里。
- **双向核对**：每条文献都在正文被引用过，每个角标都有对应条目。文献顺序调整后，手工编号的角标全部重编。

## 图

- 所有图用脚本生成，保留脚本、SVG 源文件和导出的 PNG。
  - 示意图（流程图、架构图、追溯链条图）：用 `scripts/figures/figlib.py` 按坐标排版，输出 SVG 和 2 倍分辨率 PNG（依赖 matplotlib）。一图一脚本，写法见 `example_diagram.py`。
  - 数据图：matplotlib，300 dpi，同时输出 PNG 和 SVG。数据写在脚本里，用断言核对合计与原始台账一致。写法见 `example_datachart.py`。
- 全文一套风格，集中写在 `figlib.py` 的 `STYLE` 和 `C` 里，单张图里不另写颜色值：衬线中文字体；灰黑线条和文字，底色只用白和浅灰两档；只用一种强调色，问题或断点用红色；企业外部的环节用虚线框；画布宽度和字号全文一致；图里不写图题，图题由 Word 生成。
- 中文字体先确认可用。Windows 上有宋体可直接用；Linux 上 matplotlib 读字体集合（.ttc）容易选错语言，用 `extract_cjk_font.py` 取出简体中文字形单独加载。
- 图中名称与正文和标题一致，标题改了就重新生成对应的图。作者自评性质的图（如能力成熟度雷达图）在图注里注明“作者自评”。
- 常用的图：技术路线图（近乎必备）、理论框架应用路径图、组织结构图、工艺或业务流程图、现有与改进后的系统架构图、改进前后流程对照图、数据趋势图、能力对比雷达图。图的数量以本院范文实测为准，不凑数。
