# 源稿约定（Markdown → Word）

生成脚本按下面的约定解析源稿。写作时遵守这些约定，合稿才能一次成功。

| 写法 | 含义 |
|---|---|
| `#` / `##` / `###` + 编号 + 全角空格 + 标题，如 `## 3.1　YT公司概况` | 章 / 节 / 小节。编号手写，不用 Word 自动编号 |
| `![图 x.x](路径)`，紧接下一行 `【图 x.x　图题】` | 插图和图题。路径存在就按路径取图；不存在则按“图x.x_”前缀到配置的图片目录找。路径主要供 Markdown 预览用 |
| `【表 x.x　表题】`，后面接 Markdown 表格 | 表题和表格。表题在表上，图题在图下，脚本自动处理 |
| 图或表之后的 `> 资料来源：…`、`> 注：…` | 图注、表注，会输出到 Word |
| 其他以 `>` 开头的行 | 写作备注（版本、依据、待办提醒），不输出 |
| `<sup>[n]</sup>` | 引文角标 |
| `**…**` | 加粗。正文里少用；表格内容不加粗（表头由脚本加粗） |
| `## 本章待…` 及其后的全部内容 | 章末待办区，不输出。所有 `[需补充]`、`[参考文献]` 占位在这里登记 |
| 摘要文件：第一段是论文题目；`**关键词：**` 单独一行，关键词另起一行以全角空格开头；`# Abstract` 之后是英文摘要，格式相同 | 中英文摘要 |
| 参考文献文件：以一级标题“参考文献”开头，每条写作 `[n] …` | 参考文献表，悬挂缩进 |
| 章文件名：`第N章-标题.md`（可在配置里改匹配规则） | 按 N 排序合稿 |

## 一个完整的小节长这样

```markdown
### 3.3.2　过程检验流于形式，质量依赖末端把关

> 依据：04-数据解读 第二节；2025-03-12 作者确认首件检验由班组长执行

注塑件的尺寸与外观缺陷大多可以在首件和巡检环节发现。公司规定每次开机和换模后须做首件检验，但抽查近三个月的记录，按规定执行的约占六成<sup>[12]</sup>。……

【表 3.3　YT公司过程检验执行情况】

| 项目 | 现状 | 影响 |
|---|---|---|
| 首件检验 | 按规定执行的约占六成 | 批量不良风险 |
| 巡检记录 | 多在班次结束时补填 | 不能反映实际状态 |

> 资料来源：YT 公司提供。
```
